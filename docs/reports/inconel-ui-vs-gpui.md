# Inconel UI와 GPUI 렌더링 비교

2026-11-23에 Apple M4 Pro에서 Rust 1.97.1 릴리스 빌드와 `gpui-pre 0.3.12`로 측정했다. 모든 구현은 동일한 32 × 32 타일 그리드에서 같은 순서로 색을 바꾼다. 단순 타일에는 색 배경 하나가 있고 복합 타일에는 색 배경과 자식 요소 여덟 개가 있다.

| 구현 | 갱신 방식 |
| --- | --- |
| GPUI 루트 갱신 | 루트 엔티티에 알리고 전체 `div` 그리드를 다시 구성 |
| GPUI 캐시 | 바뀐 타일 엔티티에 직접 알리고 `AnyView::cached`로 나머지 타일을 재사용 |
| Inconel | `Signal::set`이 구독 뷰에 알리고 같은 GPUI 캐시를 사용 |

프레임마다 바뀐 값을 하나의 GPUI 업데이트에 적용하고 테스트 창이 그리도록 했다. jmark는 각 접근에서 30프레임 실행과 30+N프레임 실행을 각각 10회 측정하고, 실행 시간 중앙값의 차이를 N으로 나눴다. 단순 타일의 N은 400, 복합 타일의 N은 160이었다.

## 프레임당 경과 시간

단위는 ms/frame이다.

| 조건 | GPUI 루트 갱신 | GPUI 캐시 | Inconel |
| --- | ---: | ---: | ---: |
| 단순 타일 1개 변경 | 0.844 | 0.899 | 0.912 |
| 단순 타일 1,024개 변경 | 0.880 | 1.687 | 1.891 |
| 복합 타일 1개 변경 | 11.876 | 4.614 | 4.543 |

렌더 호출을 별도로 검사했다. 한 타일을 바꾸는 경우 루트 갱신은 프레임당 1,024개, GPUI 캐시와 Inconel은 1개를 렌더했다. 모든 타일을 바꾸는 경우 세 방식 모두 1,024개를 렌더했다. 호출 계측은 시간 측정에서 껐다.

복합 타일을 하나씩 갱신할 때 Inconel은 루트 갱신의 2.61배 속도였고, 직접 GPUI 캐시 대비 프레임 시간 비율은 0.98배였다. 단순 타일의 희소 갱신에서는 호출 감소가 프레임 시간 개선으로 이어지지 않았다. 단순 타일을 모두 바꿀 때 Inconel은 루트 갱신 시간의 2.15배가 걸렸다. 타일 단위 갱신으로 절약되는 하위 트리 작업이 커질 때 캐시의 효과가 나타났다. 복합 타일 측정에서는 1%대 실행 간 변동과 비슷한 크기의 차이가 두 캐시 방식 사이에서 관찰됐다.

## 측정 범위

GPUI 테스트 백엔드에서 상태 갱신, 뷰 구성, CPU에서 실행되는 레이아웃과 페인트 경로를 포함했다. 실제 창의 GPU 제출, 디스플레이 동기화, 입력 지연은 측정 범위 밖이다. 구현마다 독립 프로세스로 순차 실행했으며 긴 실행의 변동계수 최댓값은 4.4%였다 (`dense`, `flat`). 단순 타일과 복합 타일로 나눈 조건에서 얻은 결과이므로 앱 전체의 FPS에는 직접 적용할 수 없다.
